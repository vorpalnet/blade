Sections Reference

JVM

JVM arguments per target: what the JVM starts with on the next boot. All restart-required.

KnobTypical valueEffect
-Xmssame as -XmxInitial heap size; pinning to max avoids reallocation pauses.
-Xmx4–16 GB for engine tierMaximum heap. Sized for expected concurrent sessions × per-session overhead.
GC algorithm-XX:+UseG1GC for mostPicks the GC strategy. G1 for low-pause requirements; ZGC for very large heaps.
GC log-Xlog:gc*:file=...Where GC events get written; essential for any sizing investigation.

A profile is a named set of arguments. The structured form (heap, GC, the modeled WebLogic/OCCAS -D properties, JFR) and the raw Arguments box edit the same string and stay in sync; unmodeled arguments are kept.

A target is a ServerStart owner in config.xml: a static server (the AdminServer, engine0) or the engine server template. A dynamic engine has no ServerStart of its own; it boots from its cluster's template, so the template is the row to assign. Assign a profile to each target, then Preview. The preview shows, per target, which knobs are added, removed or changed, which existing arguments are kept, and any warnings (a Metaspace cap where the server had none, a pinned heap sum the admin box cannot hold, a classpath without the SIP jars). Apply writes the same diff. A profile is an overlay: an argument it does not mention stays as it was, which is what keeps -Dwls.home and the call-state manager on the line when a profile is silent about them.

Details on a target row shows its live arguments, JDK and ClassPath. The ClassPath is editable there because in MBean-mode start Node Manager builds the java line from ServerStart alone: a classpath without weblogic_sip.jar boots a server with no SIP container.

History & baseline. The baseline is every target's ServerStart as install.sh left it, pinned the first time the page sees the domain and rewritten only by Re-baseline. Every apply, restore and classpath save first records the state it is about to replace; the last twenty are kept. Restore baseline on a row, or Restore… on a history entry, writes ClassPath and Arguments back verbatim, no merge. That is the way back when a tuning change stops a server coming up.

SIP Timer

The SIP timer table per RFC 3261 §A. Tuning these affects retransmission cadence and dialog teardown. Restart-required — the engine reads the timers once at startup (a static initializer in the transaction layer), so a change is persisted to sipserver.xml on activate but does not affect a running engine until that node restarts.

TimerDefaultWhat it controls
T1500msRound-trip estimate. Floor for retransmission intervals.
T24sMaximum retransmission interval for non-INVITE.
T45sMaximum duration a message persists in the network.
Timer F32s (64·T1)Non-INVITE transaction timeout.

Increase T1 on lossy / high-latency networks; decrease only if you've measured and know you can.

Send 100 for Non-INVITE (BEA-331601)

The behavior checkbox with the least obvious meaning. RFC 4320 permits a server to answer a non-INVITE request with 100 Trying once the client's retransmission interval has backed off to T2. OCCAS implements that as a guard timer, on by default — the default is compiled into the descriptor bean, so an empty sipserver.xml means enabled: every non-INVITE server transaction (every REGISTER, SUBSCRIBE, OPTIONS, …) arms a timer at T2 (4 s), and if the application has not answered by then the container sends 100 Trying itself.

Applications that answer in milliseconds never benefit, but they can still pay: when a request ends up answered through a different path than the transaction the timer watches — the classic case is a retransmission processed as a fresh request while the original dispatch was stalled behind a session invalidation — the timer fires, finds the transaction already completed, and the engine logs BEA-331601 <Client timer task failed with fatal status> java.lang.IllegalStateException: This transaction has been completed already at ERROR severity. The message says "client timer" but it is the server transaction's guard; the label is a shared catch-all in the transaction layer.

If BEA-331601 appears in your engine logs on REGISTER or SUBSCRIBE traffic, uncheck this box. The error is harmless — the endpoint always recovers by retransmission — but each occurrence is an ERROR-severity line and a retransmission delay you can remove.

How WLS schedules incoming work across threads. Runtime-tunable.

KnobTypicalEffect
Min threads5Lower bound on the work-manager pool.
Max threads50–200Upper bound. Set to roughly 4× CPU count for I/O-bound workloads.
Capacity constraint50000Max queue depth before requests are rejected. Backpressure setting.
Fair-share class50Relative scheduling weight when multiple work-managers compete.

Cluster

Cluster membership view (mostly read-only) plus the heartbeat knobs. Read-only members; heartbeat is runtime-tunable.

Members
Read-only list of servers in the cluster, including their listen address and current state.
Messaging mode
Unicast (preferred) or multicast. Unicast scales better and traverses routers; multicast needs a switched LAN.
Heartbeat interval
How often each member announces itself. Lower = faster failure detection but more network chatter.

Server Tuning

Per-server execute-queue and socket tuning. Mostly runtime; native-I/O toggle is restart-required.

Accept backlog
OS-level listen queue depth. Increase for high-burst clients (default 50 is low for production).
Socket receive/send buffer size
TCP buffer tuning. Defaults are usually fine; bump only after measuring.
Native I/O
Toggle WLS native socket muxer vs. pure-Java. Native wins for high concurrency; the toggle requires restart.
Min Severity to Log
Floor for the server's own log stream (WebLogic Log MBean's MinimumSeverityToLog). Runtime-effective, no restart. Quiets chatty subsystem Notice-level noise without touching application logging config.
Always measure

Every "typical value" above is a starting point. Productionize tuning is workload-specific — measure before and after every change. If the change doesn't show on a graph, it didn't happen.
