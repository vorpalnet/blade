What the designer does

Describe an event once. The payload class, its JSON Schema, a consumer already bound to the right selector, a producer snippet and a sample envelope all regenerate as you type — from the same declaration, so none of them can drift from the others.

Fields

The wire name is what appears in the JSON. A snake_case name becomes a camelCase Java property with the wire form preserved by @JsonProperty — the bytes never change shape to suit Java.

Persist

The analytics sink writes events marked persist to the database. It reads the flag from the live catalog per message, so turning it on takes effect without a redeploy.

Subscriber identity

Who listens is a separate declaration from what an event is, because several applications may want the same event and each needs its own subscription identity to receive its own copy. Two subscribers sharing a name are not two subscriptions — they are one subscription named twice, and the two applications compete for a single stream.

Name the subscriber, not the event. The name becomes the JMS client id, the durable subscription name and the consumer's class name.

Filtering — at the broker or in code

A derived selector filters at the broker and fails closed: an event type nobody added is never enqueued. Filtering in code takes everything on the destination and fails open — right for a sink whose job is to miss nothing, at the cost of holding messages it will drop.

Durable

A durable subscription holds events while the subscriber is down. On for a sink; consider off for something that takes action, where a stale action can be worse than a missed one. Ignored on a queue. Delivery is at-least-once either way — a subscriber that acts must tolerate seeing an event twice.

Generated source

Source only — the server never compiles this or publishes a jar. The wire contract is the schema. The consumer module goes into the consuming application's own source tree, never into the framework: every BLADE WAR bundles the framework jar and EJB scanning covers WEB-INF/lib, so a consumer placed there would activate in every deployed application at once, all of them contending for one client id.
