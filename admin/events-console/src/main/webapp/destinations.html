Destinations

The domain's JMS resources with their live numbers. Nothing in BLADE has ever read a JMS runtime MBean, so depth, pending count, consumer count and durable-subscription state have simply been invisible until now.

New destination
Its own quota, so one destination cannot fill a shared store and starve the others.

An existing BLADE JMS module is adopted rather than duplicated — WebLogic cannot rename a JMS resource, and destroy-and-recreate would orphan its file store.

					Durable subscriptions
					—
				

				

					

						A subscription's selector is the one thing that decides whether it
						receives anything. If it does not match what the publisher stamps,
						the subscription gets nothing — and that is indistinguishable from
						no events being published.

					Messages
					
				

				

					

						Non-destructive: this reads what is at rest through a cursor and
						takes nothing, so it cannot steal a message from the real
						consumer. Bodies are truncated for display. Every browse is
						logged with your username — an event body carries the call
						correlator and whatever the producer put in it.
