API Contract

Base path

Every endpoint is served by this WAR itself, under its own context root: /blade/crud-editor/resources/api/ (written {base} below). These are the editor page's private backend — not an API the CRUD service exposes. Every code path returns application/json, even on error, so the page can always parse what it receives.

Endpoints

MethodPathPurpose
GET{base}/ruleSetsList the rule-set ids in the live config — populates the dropdown.
POST{base}/selectionSelection dry-run: run the enrichment pipeline against a pasted SIP request and report which rule set it selects.
POST{base}/previewRule dry-run: replay a pasted SIP message through a named rule set and return the transformed result.
GET{base}/configLoad the config document and its JSON Schema for the rules editor: {source, config, schema}, where source is live, sample, or builtin.
POST{base}/config/saveSave: body is the full config document. Rejected (400) if the CRUD service couldn't load it; credentials encrypted; previous file backed up to .versions/.
POST{base}/config/publishPublish: reload the saved config on every node running the CRUD service (409 when the service isn't deployed).
GET{base}/config/versionsList .versions/ snapshots: {versions:[{timestamp,sizeBytes}]}.
GET{base}/config/versions/{ts}One snapshot's content.
POST{base}/config/versions/{ts}/restoreRestore a snapshot (the replaced file is backed up first).

The two dry-run endpoints also accept optional draftRuleSets, draftDefaultRuleSet, and draftPipeline fields — the rules editor's unsaved buffer — which replace the live config's rule sets for that run only.

The servlet re-reads the live config/custom/vorpal/crud.json on every request, falling back to the built-in sample when no config has been published yet.

Selection dry-run

POST {base}/selection — body: 

{
  "message":   "INVITE sip:8003@pbx.example.com SIP/2.0\r\n...",
  "variables": { "name": "value", ... }   // optional pre-set session state
}

Response:

{
  "ruleSet":   "example-update",          // null = passthrough (no match, no defaultRuleSet)
  "variables": { "dialedNumber": "8003", ... },  // post-enrichment session snapshot
  "warnings":  [ "..." ],                 // captured engine log lines (table misses etc.)
  "error":     null
}

Rule dry-run

POST {base}/preview — body: 

{
  "ruleSet":        "example-update",
  "lifecycleEvent": "callStarted",        // null skips event filters
  "message":        "INVITE ... SIP/2.0\r\n...",
  "variables":      { "name": "value", ... }
}

Response:

{
  "output":     "INVITE ... SIP/2.0\r\n...",   // transformed message
  "rulesFired": [ "rewrite-everything" ],
  "variables":  { ... },                  // session snapshot after the run
  "warnings":   [ "..." ],
  "error":      null
}

error non-null (HTTP 400) means the run itself failed — unparseable message, unknown rule set, missing config. warnings carry per-operation errors the engine swallowed so the transformation could continue.

Authentication

All endpoints inherit the BLADE admin tier's session auth (Admin and Operator roles). No separate token; the same login that opens the portal opens the preview API.
