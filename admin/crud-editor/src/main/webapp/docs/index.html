Welcome

The CRUD Editor authors the CRUD service's rules — the pipeline that selects a rule set for each call, and the rule sets that transform the selected calls — with a live preview that replays every unsaved change against a pasted SIP message before anything is saved or published. The editor's built-in ? Help dialog explains each concept in place; these pages are the reference companion.

Reading order

  1. Overview — the CRUD service, the three-step editing model, and the division of labour with the Configurator.
  2. API Contract — the preview and config endpoints the editor page calls.
  3. Troubleshooting — the common failure modes and what to look at next.

At a glance

Editsconfig/custom/vorpal/crud.json — the pipeline, default rule set, and rule sets; logging and session stay in the Configurator
PreviewRuns the unsaved draft through the production engine in-process on the AdminServer; nothing touches the wire
Save / PublishSave validates and writes the file (previous version kept); Publish reloads the running CRUD service via its Configuration MBeans
