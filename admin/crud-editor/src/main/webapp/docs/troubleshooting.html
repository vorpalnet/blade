Troubleshooting

SymptomLikely causeWhat to do
Connector or operation forms show raw JSON instead of fields The editor couldn't load or resolve the JSON Schema — the raw-JSON textarea is the deliberate no-data-loss fallback Check the browser console and hard-refresh (the kit script /blade/portal/lib/blade-editor.js may be cached stale). If _schemas/crud.jschema is missing, the editor generates one in-process — a failure there means a framework-version mismatch between the portal and this WAR.
Auto-select reports no rule set for a message that should match The pipeline's regex didn't extract, or the table key doesn't match Read the variables the selection returned — if dialedNumber (or your key variable) is missing, the selector's pattern didn't match the pasted message. Warnings from the engine (table misses log at FINER in production) appear under the preview.
A rule doesn't fire in preview One of its filters failed: method, messageType, lifecycle event, statusRange, leg, sdp, or when Check the lifecycle-event dropdown matches the rule's event filter; a rule with no event never runs on receive. A statusRange restricts the rule to responses. Set the preview's Leg and "Request had SDP" controls to the case you mean. A when that does not parse never fires: Save refuses one, and a file edited by hand logs Rule[id] - when … cannot be evaluated once.
A rule fired but the message is unchanged One of its operations failed, so the whole rule was undone Look in the application's log for Rule[id] - operation N failed, rule undone; it names the operation and the exception. Common causes: writing status on a request, writing a read-only attribute (originIP, peerIP, transport, isSecure), or changing a 2xx status.
An operation did nothing, and its rule fired A ${name} in its value, pattern or path has no value, so the operation was skipped Placeholders resolve from session variables only. Make sure an earlier read sets the variable. For an environment variable or system property write ${env:NAME} or ${sys:NAME}. The skip is logged at FINE.
Save says "not saved: N problem(s)" A when, status range, regex, XPath or JsonPath does not compile, defaultRuleSet names no rule set, or (domain file) a saved test no longer gives its result The list under the toolbar names each one: rule set, rule, operation, and for a read the variable; a test by name, with the first line that differs. Every preview refreshes the rule checks; Run tests refreshes the tests. If a test's change is intended, run it and click update. Nothing was written.
Save returns 400 "config rejected" The document wouldn't load in the CRUD service — unknown operation type, unknown field, malformed shape Read the error: it's the actual parse failure the service would have logged. Nothing was written; the live config is untouched.
Publish returns 409 No Configuration MBean for crud — the CRUD service isn't deployed or isn't running The file IS saved. Start or deploy the crud service, then publish again — or wait; a node picks the file up at its next start.
Published, but the running service behaves like the old config The reload happened on a node that doesn't share this domain directory, or the publish reloaded before the save you meant Check the vorpal log on an engine node for the configuration-reload lines; confirm the JSON panel matches what you expect, then Save and Publish in that order.
Editor returns 401 on every request Session expired Re-login via the portal.
Preview before you publish

One wrong rule affects every call its filters match. The preview runs the exact engine production runs — paste a captured message and prove the change before Save, and again before Publish. The few extra seconds are worth more than a recovery story.
