WebRTC Phone

A browser as a first-class SIP endpoint. This page speaks JSON events over a WebSocket to OCCAS — not SIP — while the network sees an ordinary SIP call. Media is anchored on a media server that terminates ICE and DTLS-SRTP on this side and emits plain RTP on the other.

Dial another browser and the call runs peer‑to‑peer — no media server, nothing to deploy but BLADE. Dial a phone number and the call is anchored on a media server, because a phone cannot speak ICE or DTLS.

Signaling log

    Pressing Record on a peer‑to‑peer call pulls a media server in. That is not a tap: the two browsers hold DTLS keys derived from a handshake with each other that this server never saw, so both legs have to be re‑offered and re‑keyed. Expect a brief gap in the audio when it happens — that is the renegotiation, not a fault.

    If the call connects but there is no audio, the signaling above will look perfect — it is almost always NAT traversal. Browsers publish <uuid>.local mDNS candidates instead of private addresses, so both this browser and the media server need a reachable STUN or TURN server, and a cloud-hosted media node needs its public address configured (external.ipv4) or it will advertise one nothing can reach.
