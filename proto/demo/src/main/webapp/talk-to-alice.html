What happens on the call

  1. You dial → BLADE answersThe INVITE arrives over a real PSTN trunk; FSMAR routes it to the voice agent. No SBC, no media gateway in between.
  2. Alice greets youHer opening line is synthesized on‑CPU and returned over symmetric RTP — the audio path is set up before you say a word.
  3. You speak → recognized on‑netStreaming ASR on Ampere cores turns your voice into text as you talk. The audio never leaves the network.
  4. She thinks, then answersThe transcript is answered by an LLM; the reply streams back sentence‑by‑sentence, spoken on‑CPU, about two to three seconds after you stop.
  5. Hang up → call releasedEither side hangs up and BLADE tears the whole call down cleanly.

Honest caveat — where the data goes

The audio stays on‑net. Recognition and synthesis both run on CPU inside the network — the call's audio never reaches a third‑party cloud.

The LLM is the cloud Claude API. Only for the thinking step: the transcript text of what's said is sent to the Claude API and the reply comes back as text. That text does leave the network. A fully on‑net language model is on the roadmap — the infrastructure (log‑mel front end, int8 runtime) is in place; the on‑CPU model is the remaining piece.

Alice says this herself if a caller asks how the call works — the honesty is built into the persona.

Live on the ashburn cluster — not a mockup. On‑net ASR + TTS on OCI A4; LLM via the cloud Claude API.
